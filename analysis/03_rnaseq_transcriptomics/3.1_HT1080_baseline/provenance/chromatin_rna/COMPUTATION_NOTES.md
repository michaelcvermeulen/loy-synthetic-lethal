# Computational implementation notes

The statistical configuration and all 14 input hashes were frozen before testing. The initial serial runner was distributed into four deterministic test partitions to reduce elapsed time. Test seeds depend on the fixed test index, not worker scheduling; completed tests were retained.

Two passage-omission scenarios initially produced two unestimable GSEA P values each, triggering the prespecified 100,000-permutation retry. The fgsea 1.36.2 multi-pathway cumulative-prefix kernel was unusually slow for these approximately 10,000-gene sets. Inspection of the installed package confirmed a distinct, public single-pathway calculation in `fgseaMultilevel`; a non-inferential runtime check of 1,000 draws on the H3K4me3 set took 5.94 seconds. No benchmark P value is included in the analysis.

The unfinished batched retries were stopped and restarted using the same public `fgseaMultilevel` test separately for each failed pathway, with two local R workers per retry. The retry still uses exactly 100,000 initial permutations, exponent 1, score type `std`, eps 1e-10, the full frozen ranking and the same documented retry seed (initial seed +10,000). Each single-pathway call resets that seed. The single-pathway algorithm generates a different deterministic Monte Carlo realization from the multi-pathway kernel, with the same gene-set null and target statistic. This is a computational change, not a change in hypotheses or eligibility. Completed primary, period and sensitivity tests were retained. Final BH/BY correction is applied across the complete 20-set family after recombination.

Partition-local completed results are reused when resuming after interruption, subject to the frozen input checks. A failed estimate that persists after the prescribed retry remains explicitly missing and unrejected; the runner does not repeatedly escalate the permutation count. The actual initial/retry seeds and `nPermSimple_used` are exported for each result.
